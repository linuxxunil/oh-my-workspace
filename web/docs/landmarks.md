# Page Landmarks / 页面地标

地标组合归路由布局与业务组件共有，按 W3C 地标语义与基元命名契约执行，本指南只记 Web 侧如何落地。

## 归属

- 可感知内容放有意义地标区，组合布局与子项后检查覆盖。
- 加页面地标前先追父布局（含平行路由槽与传送），不单看一个组件。
- 主布局提供 `main` 与跳链目标，后代页与编辑器不再建第二个 `main`；隐藏主导航不移除该包层；布局外路由自建主内容边界。
- 跳链与其目标同属一布局 owner；换包层保留目标 ID 与焦点行为，地标角色本身不移动焦点。
- 标题不建地标，不自动命名所在区。

## 按内容选角色

- `nav` 给有意义导航链接组；资源卡网格能开详情不自动算导航。
- 视觉侧栏不自动算补充内容；文件控件、编辑器、构建面板属当前任务，按导航价值用普通容器或命名区。
- 命名 `section` 只给值得直达的内容；不把每个包层、卡片、弹窗体变地标；命名优先复用可见标题。
- 重复地标按用途区分命名；名称本地化，不复述角色。
- 页级 `header/footer` 可暴露横幅与页脚；局部面板头脚不一定暴露，先查组合上下文再加显式角色。

## 验 composed 页

- 查主边界、地标层级、名称、标题关系，覆盖加载、空态、折叠、浮层打开四态；隐藏骨架不计入地标清单；条件内容变化重查标签引用。
- 改语义元素连带查单测与 E2E 定位（含 `closest('main')` 类选择器），定位到业务控件，不靠加地标或位置序号。
- 回归覆盖走测试政策；组合边界保持拥有地标语义的组件为真，不拿 mock 侧栏证明真侧栏角色。
