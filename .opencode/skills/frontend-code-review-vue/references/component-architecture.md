# Component Architecture Review (Vue) / 组件架构评审

评审组件划分是否贴合行为归属，模块边界是否清晰。

## Vertical Modules / 垂直模块

- 按路由与行为归属方组织目录：组件、组合函数、类型、存储片段、查询辅助、测试放在同一模块内。
- 跨模块只经过公开入口引用；不写只做转发的桶文件；不设 `common.ts` 式杂物箱。
- 只有多个模块共用且契约稳定时才上提共享层；将来可能复用不构成上提理由。

## Ownership / 归属

- 状态、数据、加载态、空态、错误态、事件处理放在最低可用归属方，并与挂载周期和存活需求匹配；只有需要跨卸载存活、统一快照、协调提交或选择或导航时才上提到父级。
- 同一查询键在兄弟组件间共享缓存，不构成状态上提的理由；`defineProps`、`defineEmits`、`slots` 使用领域命名，保持与生成契约的可追溯关系；不把枚举、联合类型、可空类型提前放宽为普通字符串。
- 不用庞大的视图组合函数代替属性传递；不用共享状态掩盖归属不清。
- 页面区块加载态使用局部骨架屏；小型行内忙态才用 spinner。

## Boundaries / 边界

- 优先复用已经拥有该交互的组件，不平行重建；新建包装层必须真正拥有行为、校验、状态、无障碍、布局、外部库集成之一，否则删除。
- 模块逻辑不进入共享组件：不用一串布尔属性编码某个具体模块，不把该模块的文案、路由、接口契约引入通用组件。
