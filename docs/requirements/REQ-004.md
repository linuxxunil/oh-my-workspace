# REQ-004 模型按类型字段 + 密码两步走

> Origin: 用户 2026-09-29 三定项——模型“新建补字段+可编辑”；密码“都要，分两步”；下批为画布美化二期（本轮只记录，不做）。

- 背景 / Background：供应商后端早有 `api_key`（只收不返）+ `extra_headers`，前端新建只有三栏且无编辑接口（改 Key 靠删建）；密码链 `PATCH` 仅管理员可用，member 自改完全不存在，前端无任何密码入口。
- 目标 / Goals：
  1. 模型：新建表单按类型出字段（名称/LLM 地址/API Key 密码框，留空=不设）；新增 `PATCH /models/providers/{id}`（改名/地址/Key，`api_key=""` = 不修改）；行内编辑。
  2. 密码 A：管理员在用户页重置他人密码（后端现成，走 `PATCH /users/{id}`）。
  3. 密码 B：本人自改，新 `POST /auth/password {old_password, new_password≥8}`（authn-only，无新权限码；旧密码错 400），独立 `/account` 页。
- 非目标 / Non-goals：`extra_headers` 前端暴露（二期）；供应商删除二次确认；全站暗色；画布美化（下批 PLAN-005）。
- 验收标准 / Acceptance Criteria：
  1. AC1 模型：`PATCH` 403（member）/404/409（改名冲突）/Key 留空不覆盖均有单测；前端两类型均见三栏 + 行内编辑保存生效；`@smoke` 新增换 Key 场景绿。
  2. AC2 重置：管理员行内重置后，新密码登录 200、旧密码 401（e2e 浏览器断言）；admin 动 super_admin 仍 403。
  3. AC3 自改：三角色均可自改；旧密码错 400；改后新密码可登录；`@smoke` 或独立场景覆盖。
  4. AC4 契约卫生：`make openapi-check` 绿（改 schema 必重生成双客户端）；i18n 中英同步；e2e 旧锚点零改动。
- 约束 / Constraints：RBAC 唯一小决策——自改端点 authn-only（对标 `/auth/me`）；Key 只收不返；密码最小 8 位沿用；Vue3 禁 React；Tailwind canonical；基元复用。
