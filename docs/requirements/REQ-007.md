# REQ-007 extra_headers 端到端暴露

> Origin: REQ-006 非目标排队项；用户 2026-09-29 批复定项——只收不返 / KV 行编辑 / 禁止覆盖 Authorization / 新建+编辑+e2e。

- 背景 / Background：`extra_headers` 后端已存（`ModelProvider.extra_headers` JSON 列，create/update 收、`_auth_headers` 发时合并），但 `ProviderResponse` 不返、前端零入口（`ModelsView.vue` “二期再开”），写了用不上。
- 目标 / Goals：
  1. 后端 create/update 校验 headers 键规则，非法→400；合法头随请求透传。
  2. 前端新建表单 + 行内编辑表单各加 KV 行编辑器；编辑语义与 api_key 对称：空=保持，填了=整体替换。
  3. e2e 一新场景：建供应商填自定义头→保存→连通性仍 ok。
- 非目标 / Non-goals：Response 回显（只收不返）；通用 KV 基元进 `packages/ui`；缓存策略；历史版本/画布/矩阵。
- 验收标准 / Acceptance Criteria：
  1. AC1 后端：`authorization`（大小写不敏感）→400；非法键名→400；值超长/超条数→400；合法头透传（单测断言发出 headers 含自定义头且 `Authorization` 为 Bearer）；PATCH 为整体替换；既有用例回归绿。
  2. AC2 前端：新建+编辑均有 KV 行编辑器（增/删行，空行忽略）；hint 写清“留空=保持，填写=整体替换”；`models.*` 文案中英同步。
  3. AC3 e2e：新场景绿；旧锚点零改动。
  4. AC4 卫生：`ProviderResponse` 不动，`openapi-check` 绿；i18n 同步。
- 约束 / Constraints：只收不返（与 api_key 对称）；键 `^[A-Za-z0-9-]+$`、值 ≤1024、≤20 条；沿用 `models:write`；校验收敛 service 层共用 helper，`ValueError→400` 走现有通道。
