# REQ-006 供应商删除补齐 + 绑定拒绝

> Origin: 用户 2026-09-29 反馈——模型页缺删除键；被流程绑定的供应商应拒绝删除。

- 背景 / Background：后端 `DELETE /models/providers/{id}` 早已存在，前端行无删除键；引用关系只存在版本 DAG JSON（llm 节点 `config.provider_id`），无外键，误删后运行时才炸。
- 目标 / Goals：
  1. 后端删供应商时检查本租户各流程**最新版本** DAG，被引用即 409 并报流程名。
  2. 前端每行删除键：原生 confirm（`models.confirmDelete`，含供应商名）→ 删 → 刷新；409 行内 `role=alert` 显示原因。
- 非目标 / Non-goals：历史版本引用检查（快照不管）；dialog 基元；extra_headers（下批 PLAN-007）。
- 验收标准 / Acceptance Criteria：
  1. AC1 后端：被引用删→409 且供应商仍在；无引用→204；member→403；`PATCH` 等既有用例回归绿。
  2. AC2 前端：删除键存在；confirm 取消不删；确认删后列表消失；被引用时红字出现且行仍在。
  3. AC3 e2e：新增“删除”与“被引用拒绝”两场景绿；旧锚点零改动。
  4. AC4 卫生：i18n 中英同步；`openapi-check` 绿（无 schema 变更则更须绿）。
- 约束 / Constraints：只查最新版本（运行只用最新）；Key/confirm 文案进 locales；沿用 `models:write`。
